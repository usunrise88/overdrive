# Overdrive 0.2.0

Этим релизом закрыт этап 2 (Phase 2, спецификация §5): заезды уходят с планшета на ваш сервер и в intervals.icu, на
планшете появляются запланированные тренировки, ИИ-клиент может планировать через MCP, а календарь, Telegram и Strava
получают данные автоматически. Выходит одним релизом, без альф.

**Ничего из этого не проверено на вашем аккаунте.** Сервер и планшет собраны и проверены автоматически, на поддельных
intervals.icu, Google, Telegram и Strava, которые написаны по тем же заметкам API, что и код. Зелёный тест значит «согласуется
с заметками», а не «работает с вашим аккаунтом». Первый запуск сервера и первый заезд с выгрузкой — это ваша проверка.

This release closes stage 2 (Phase 2, spec §5): rides leave the tablet for your server and for intervals.icu, planned workouts
appear on the tablet, an AI client can plan over MCP, and the calendar, Telegram and Strava receive data automatically. It is one
release, with no alphas.

**None of this has been checked with your accounts.** The server and the tablet app are built and tested automatically, against
fake intervals.icu, Google, Telegram and Strava services written from the same API notes as the code. A green test means "agrees
with the notes", not "works with your account". The first start of the server and the first uploaded ride are your check.

## Что нового

- **Заезды уходят на сервер.** После каждого заезда планшет отправляет запись (JSON) и файл FIT на `https://overdrive.llmto.day`.
  Отправка повторяемая: заезд, пришедший дважды, хранится один раз. Без адреса и токена всё работает как раньше, заезды ждут
  в очереди (ADR 0014).
- **Заезды в intervals.icu без ручных шагов.** Сервер сам загружает FIT в intervals.icu и пытается привязать заезд к тренировке
  того дня. Если intervals.icu недоступен, загрузка повторится; планшет об этом не знает (ADR 0016).
- **Запланированные тренировки на планшете.** На экране **Ready** раздел **Planned**: тренировки из календаря на сегодня и
  «This week». Заезд, начатый из тренировки, привязан к ней; законченная помечается «Done» (ADR 0017).
- **Планирование через ИИ-клиент (MCP).** Сервер говорит по MCP с OAuth. Клиент, которому вы дали доступ паролем, создаёт,
  меняет и удаляет тренировки, читает заезды и профиль (FTP, зоны, доступность). Все числа считает код, не модель (ADR 0018).
- **Google Calendar и Telegram.** Тренировки зеркалятся в отдельный календарь Google (только из intervals.icu, в одну сторону).
  Telegram-бот отвечает только вашему чату: напоминания вечером накануне и за час до старта, сводка после каждого заезда,
  недельная сводка, команды `/today`, `/week`, `/skip`, `/move` (ADR 0019).
- **Strava: только запись.** Каждый заезд публикуется в Strava как виртуальная поездка с коротким текстовым описанием. Сервер
  ничего оттуда не читает: единственное разрешение, которое он просит, это `activity:write` (ADR 0020).

## What is new

- **Rides leave the tablet.** After each ride the tablet sends the record (JSON) and the FIT file to `https://overdrive.llmto.day`.
  Sending is repeatable: a ride that arrives twice is stored once. Without an address and token everything works as before, and
  the rides wait in the queue (ADR 0014).
- **Rides in intervals.icu with no manual step.** The server uploads the FIT to intervals.icu itself and tries to pair the ride
  with that day's planned workout. If intervals.icu is down, the upload is retried; the tablet does not wait for it (ADR 0016).
- **Planned workouts on the tablet.** On the **Ready** screen, a **Planned** section: the calendar's workouts for today and
  **This week**. A ride started from a workout is linked to it; a finished one is marked "Done" (ADR 0017).
- **Planning from an AI client (MCP).** The server speaks MCP with OAuth. A client you approve with your passphrase creates,
  changes and deletes workouts, and reads rides and the profile (FTP, zones, availability). The numbers are computed by code, not
  by a model (ADR 0018).
- **Google Calendar and Telegram.** Workouts are mirrored into a calendar of their own, one way, from intervals.icu. The Telegram
  bot answers only your chat: a reminder the evening before and one an hour before the start, a summary after each ride, a
  weekly summary, and the commands `/today`, `/week`, `/skip` and `/move` (ADR 0019).
- **Strava: write only.** Each ride is posted to Strava as a virtual ride with a short text description. The server reads nothing
  from Strava; the only permission it asks for is `activity:write` (ADR 0020).

## Как включить

Сервер работает на вашем хосте (Docker и Caddy). Всё по `docs/deploy.md`, команды выполняются в корне репозитория, если не сказано иное.

1. **Caddy.** Скопируйте `deploy/overdrive.llmto.day.caddy` в `/etc/caddy/sites.d/`, проверьте и перезагрузите Caddy. Раздел 1.
2. **`.env`.** Задайте `POSTGRES_PASSWORD` (`openssl rand -hex 24`), `SERVER_PORT=27180`, `POSTGRES_PORT=27181` и `TIMEZONE`
   (ваш часовой пояс, например `Europe/Paris`: от него зависит, какой день «сегодня»). Разделы 2 и 11.
3. **Токен планшета.** Создайте строку `DEVICE_TOKENS=tablet:…` командой из раздела 3. Значение не показывайте никому и не
   вставляйте в чат.
4. **Запуск.** `docker compose up -d --build`, затем `docker compose logs --tail 30 server` (строка `database migrated`) и
   проверка `https://overdrive.llmto.day/healthz`, которая отвечает `{"status":"ok"}`. Разделы 4 и 5.
5. **Настройки планшета.** Settings, Sync: адрес `https://overdrive.llmto.day` и токен из пункта 3, только значение, без
   `tablet:`. Через несколько секунд «Waiting to upload» покажет «0 rides». Проверка 7.9 в `docs/bench-checklist.md`.

Необязательные интеграции. Каждая включается своими переменными в `.env`; пустое значение означает «выключено». После правки:
`docker compose up -d server`.

- **intervals.icu:** `INTERVALS_API_KEY` (ключ в настройках intervals.icu, Developer Settings) и `INTERVALS_ATHLETE_ID`. Раздел 11.
- **MCP:** `OWNER_PASSPHRASE_HASH` (хеш вашей парольной фразы, команда в разделе 12) и `PUBLIC_BASE_URL=https://overdrive.llmto.day`.
  Раздел 12.
- **Telegram:** `TELEGRAM_BOT_TOKEN` от BotFather, затем ваш `TELEGRAM_OWNER_CHAT_ID`. Раздел 13.
- **Google Calendar:** четыре переменные `GOOGLE_*` (клиент в Google Cloud и токен из `google-auth`). Раздел 14.
- **Strava:** `STRAVA_CLIENT_ID`, `STRAVA_CLIENT_SECRET`, `STRAVA_REFRESH_TOKEN` (из `strava-auth`). Раздел 15.

Секреты (ключи, токены, пароли и их хеши) живут только в `.env` на сервере. Не вставляйте их в чат, в issue или в коммит.

## How to turn it on

The server runs on your host (Docker and Caddy). Everything is in `docs/deploy.md`; commands run in the repository root unless
stated otherwise.

1. **Caddy.** Copy `deploy/overdrive.llmto.day.caddy` to `/etc/caddy/sites.d/`, validate and reload Caddy. Section 1.
2. **`.env`.** Set `POSTGRES_PASSWORD` (`openssl rand -hex 24`), `SERVER_PORT=27180`, `POSTGRES_PORT=27181` and `TIMEZONE`
   (your time zone, for example `Europe/Paris`: it decides which day is "today"). Sections 2 and 11.
3. **Tablet token.** Create the line `DEVICE_TOKENS=tablet:…` with the command in section 3. Do not show the value to anyone or
   paste it into a chat.
4. **Start.** `docker compose up -d --build`, then `docker compose logs --tail 30 server` (it says `database migrated`) and
   check `https://overdrive.llmto.day/healthz`, which answers `{"status":"ok"}`. Sections 4 and 5.
5. **Tablet settings.** Settings, Sync: the address `https://overdrive.llmto.day` and the token from step 3, the value only, without
   `tablet:`. Within a few seconds "Waiting to upload" shows "0 rides". Check 7.9 in `docs/bench-checklist.md`.

Optional integrations. Each is switched on by its variables in `.env`; an empty value means off. After any change:
`docker compose up -d server`.

- **intervals.icu:** `INTERVALS_API_KEY` (the key from intervals.icu's Developer Settings) and `INTERVALS_ATHLETE_ID`. Section 11.
- **MCP:** `OWNER_PASSPHRASE_HASH` (the hash of your passphrase, the command is in section 12) and `PUBLIC_BASE_URL=https://overdrive.llmto.day`.
  Section 12.
- **Telegram:** `TELEGRAM_BOT_TOKEN` from BotFather, then your `TELEGRAM_OWNER_CHAT_ID`. Section 13.
- **Google Calendar:** the four `GOOGLE_*` variables (a client in Google Cloud and a token from `google-auth`). Section 14.
- **Strava:** `STRAVA_CLIENT_ID`, `STRAVA_CLIENT_SECRET` and `STRAVA_REFRESH_TOKEN` (from `strava-auth`). Section 15.

Secrets (keys, tokens, passwords and their hashes) live only in `.env` on the server. Never paste them into a chat, an issue or a commit.

## Что попробовать

1. **Заезд доходит до сервера и intervals.icu.** Проедьте короткий заезд. Ожидание: через несколько секунд «Waiting to upload»
   показывает 0; в журнале сервера есть строки `ride record` и `ride fit file`; заезд есть в таблице `rides`. Если задан
   `INTERVALS_API_KEY`, за несколько минут он появляется в intervals.icu как Virtual Ride. Проверка 7.9.
2. **Запланированная тренировка на планшете.** Запланируйте тренировку на сегодня в intervals.icu (или попросите ИИ-клиент).
   Откройте **Ready**: в **Planned** есть её название, длительность и «IF». Запустите её, доедьте и нажмите **Finish**.
   Ожидание: на **Ready** она помечена «Done» с временем, при этом её можно выбрать снова; в записи заезда на сервере стоит её
   id `icu-…`; в intervals.icu заезд привязан к тренировке дня (если загрузка прошла). Проверка 7.10.
3. **ИИ-клиент создаёт тренировку.** В клиенте добавьте пользовательский коннектор `https://overdrive.llmto.day/mcp`. Откроется
   страница **Connect to Overdrive**: введите парольную фразу и нажмите Approve. Попросите создать тренировку на завтра.
   Ожидание: тренировка есть в intervals.icu; через пару минут она появляется в Google Calendar (если календарь настроен);
   на планшете она появится, когда экран **Ready** снова запросит план (выйти и вернуться или кнопка обновления). Сервер
   обновляет свой кэш сразу после записи.
4. **Telegram.** Для тренировки на завтра придёт вечернее напоминание (`REMINDER_EVENING_TIME`, по умолчанию 20:00) с кнопками
   **Skip** и **Move**. Через минуту после заезда придёт сводка: длительность, мощность, пульс, нагрузка и, если заезд привязан к
   тренировке, план против факта. `/today` покажет тренировки на сегодня.
5. **Strava.** Следующий заезд появится в Strava как виртуальная поездка с названием тренировки (или «Virtual ride» с датой) и
   описанием: шаги, длительность, средняя мощность и пульс. Карты не будет, это ожидаемо. Проверьте, что название и описание
   читаются так, как написаны (ADR 0020, раздел 7).

## What you can try

1. **A ride reaches the server and intervals.icu.** Ride a short session. Expected: within a few seconds "Waiting to upload"
   shows 0; the server log has the lines `ride record` and `ride fit file`; the ride is in the `rides` table. If
   `INTERVALS_API_KEY` is set, within a few minutes it appears in intervals.icu as a Virtual Ride. Check 7.9.
2. **A planned workout on the tablet.** Plan a workout for today in intervals.icu (or ask an AI client). Open **Ready**: under
   **Planned** it shows its name, length and "IF". Start it, ride it and press **Finish**. Expected: on **Ready** it is marked
   "Done" with a time, and it can still be chosen again; the ride record on the server carries its id `icu-…`; in intervals.icu
   the ride is paired with that day's workout (if the upload went through). Check 7.10.
3. **An AI client creates a workout.** In the client, add a custom connector at `https://overdrive.llmto.day/mcp`. A page
   **Connect to Overdrive** opens: type the passphrase and press Approve. Ask it to create a workout for tomorrow. Expected: the
   workout is in intervals.icu; within a couple of minutes it is in Google Calendar (if the calendar is set up); on the tablet it
   shows once the **Ready** screen asks for the plan again (leave the screen and come back, or press refresh). The server updates
   its own cache straight after the write.
4. **Telegram.** For a workout tomorrow, an evening reminder arrives at `REMINDER_EVENING_TIME` (20:00 by default) with **Skip**
   and **Move** buttons. About a minute after a ride a summary arrives: duration, power, heart rate, load and, when the ride is
   linked to a workout, planned against actual. `/today` lists today's workouts.
5. **Strava.** The next ride appears on Strava as a virtual ride, named after the workout (or "Virtual ride" with the date), with a
   description: the steps, duration, average power and heart rate. No map is expected. Check that the name and description read
   as written (ADR 0020, section 7).

**Everything below has not been checked with your real account or device.** Above all, nothing in v0.1.0 has yet run on the trainer,

- **Tablet:** the upload to the real address and the answer to `401` in `HttpURLConnection`; how soon the **Planned** section

- **intervals.icu:** what an upload answers and how a duplicate is handled; the pairing of a ride with the day's workout; the

  (ADR 0016, section "What only a real intervals.icu account can settle").
- **AI clients (MCP):** which clients register dynamically; their callback addresses; the **Connect to Overdrive** page on a phone and
  with a password manager; discovery by the `401` and `resource`; token refresh (rotation and the 15-second grace); operation without SSE;
  whether models write valid `create_workout` requests (ADR 0018, section "What only a real MCP client and a real account can settle").
- **Google:** the OAuth flow with a "Desktop app" client; the seven-day life of a token while the app is in "Testing"; event ids and
  `409`; list filters and time zone; calendar reminders; limits (ADR 0019, section "What only real accounts can settle").
- **Telegram:** long polling through your proxy; `deleteWebhook` and `409`; the saved offset after a restart; the rules for editing
  messages; the owner's chat id (ADR 0019, same section).
- **Strava:** whether a subscription is needed and what an attempt without one answers; the answer to an upload and how a duplicate
  is reported; `sport_type=VirtualRide` and `trainer=1`; the limits; the `activity:write` scope; refresh-token rotation; the description
  with its line breaks; the map and the streams (ADR 0020, section 8).
- **Server:** the SQL on a real PostgreSQL server and the image build run in CI (which sets `TEST_DATABASE_URL`), but nothing has yet
  run on your host: `docker compose up -d --build`, Caddy on your domain and `healthz` are checked by the first start.

## Известные проблемы

- **Click не выбирает запланированную тренировку на экране Ready.** Его десять действий управляют заездом, а не списком. Выбирайте
  тренировку пальцем или клавиатурой. Решение о действиях Click на этом экране не принято (ADR 0017, раздел 6).
- **Незашифрованный трафик разрешён для адресов `http://`.** Манифест разрешает незашифрованные запросы, чтобы работал стенд в локальной
  сети; приложение шлёт их только на адрес, который вы ввели в Settings. Обхода нет, и он не нужен, если адрес начинается с
  `https://`, как ваш (ADR 0014, раздел 8).
- **Лаги FIT не видны как интервалы в intervals.icu.** Файл содержит два круга, а intervals.icu показывает один интервал на всю
  поездку. Причина не установлена: настройка intervals.icu или сам файл. Данные и загрузка в порядке. Обхода нет
  (`docs/bench-reports/2026-11-18-first-ride.md`; ADR 0016, раздел 7).
- **Блокировка входа в MCP общая для всех.** Пять неверных паролей подряд закрывают страницу одобрения новых клиентов на 15 минут,
  и каждая следующая блокировка вдвое дольше, до суток. Блокировка касается всех, и её может вызвать любой, кто пробует пароли.
  Уже выданные токены продолжают работать; перезапуск сервера сбрасывает счётчик (ADR 0018, раздел 5).
- **Клиент, который обновляет токен параллельно дольше 15 секунд, теряет вход.** Тогда в журнале `oauth refresh token reused`, и
  клиент нужно одобрить заново (ADR 0018, раздел «What only a real MCP client…», пункт 5; `docs/deploy.md`, «Troubleshooting»).
- **Календарь Google перестаёт работать через 7 дней, если приложение согласия в режиме «Testing».** Опубликуйте его
  (`docs/deploy.md`, раздел 14). Если токен всё же истёк, в журнале одна строка с просьбой запустить `google-auth` снова.
- **Заезд может уйти в Strava дважды.** Если intervals.icu тоже отправляет заезды в Strava, Strava получит одну поездку дважды,
  и какая копия останется, решает Strava. Выключите отправку в Strava в настройках intervals.icu (`docs/deploy.md`, раздел 15).
- **Не все тренировки intervals.icu можно показать на планшете.** Вложенные повторы, шаги по дистанции, шаги «до кнопки круга»
  и цели выше 300 % FTP пропускаются; причина видна в журнале сервера и в `planned_workouts.unsupported_reason` (ADR 0016, раздел 6).
- **Планшет не создаёт и не меняет тренировки.** Это делают ИИ-клиент, Telegram-команды и календарь intervals.icu (ADR 0017, раздел 7).
- **Ровно один экземпляр сервера.** Два сервера на одной базе будут конкурировать за ротацию токена Strava (ADR 0020, раздел 2).
- **Приложение для телефона (`overdrive-companion`) остаётся заготовкой,** Phase 3 (статистика, восстановление) не построена.
- **Остаются в силе известные проблемы v0.1.0:** только правый Click, без истории заездов, один станок и один пульсометр и
  другие. Полный список в `docs/releases/v0.1.0.md`.

## Known problems

- **The Click cannot choose a planned workout on the Ready screen.** Its ten actions drive the ride, not the list. Choose the
  workout with a finger or a keyboard. What the Click should do on this screen is not decided (ADR 0017, section 6).
- **Cleartext traffic is allowed for `http://` addresses.** The manifest permits unencrypted requests so that a bench on the local
  network works; the app sends them only to the address you typed in Settings. There is no workaround, and none is needed when the
  address starts with `https://`, as yours does (ADR 0014, section 8).
- **The FIT's laps do not show as intervals in intervals.icu.** The file has two laps, and intervals.icu shows one interval for the
  whole ride. The cause is not established: an intervals.icu setting or the file. The data and the upload are fine. There is no
  workaround (`docs/bench-reports/2026-11-18-first-ride.md`; ADR 0016, section 7).
- **The MCP sign-in lockout is global.** Five wrong passphrases in a row close the page for approving new clients for 15 minutes,
  and each further lock is twice as long, up to a day. It applies to everyone, and anyone who guesses wrongly can cause it. Tokens
  already issued keep working; a server restart clears the counter (ADR 0018, section 5).
- **A client that refreshes its token in parallel for longer than 15 seconds loses its sign-in.** The log then says
  `oauth refresh token reused`, and the client must be approved again (ADR 0018, section "What only a real MCP client…", item 5;
  `docs/deploy.md`, Troubleshooting).
- **Google Calendar stops working after 7 days while the consent app is in "Testing".** Publish the app (`docs/deploy.md`, section
  14). If the token has expired anyway, the log has one line asking you to run `google-auth` again.
- **A ride can reach Strava twice.** If intervals.icu also sends rides to Strava, Strava gets the ride twice and keeps whichever copy
  it chooses. Turn off Strava upload in intervals.icu's settings (`docs/deploy.md`, section 15).
- **Some intervals.icu workouts cannot be shown on the tablet.** Nested repeats, steps in distance, steps "until the lap button" and
  targets above 300 % FTP are skipped; the reason is in the server log and in `planned_workouts.unsupported_reason` (ADR 0016, section 6).
- **The tablet does not create or change workouts.** That is done by an AI client, the Telegram commands and the intervals.icu
  calendar (ADR 0017, section 7).
- **Run exactly one server instance.** Two servers on one database would compete to rotate the Strava token (ADR 0020, section 2).
- **The phone app (`overdrive-companion`) is still a placeholder,** and Phase 3 (statistics, recovery) is not built.
- **The known problems of v0.1.0 still apply:** only the right Click, no ride history, one trainer and one strap, and the others.
  The full list is in `docs/releases/v0.1.0.md`.

## Установка

- Планшет: `overdrive-ride-0.2.0.apk`.
- Телефон: `overdrive-companion-0.2.0.apk` (пока заготовка).
- Сервер не ставится из APK. На хосте: `git pull --ff-only` и `docker compose up -d --build` (`docs/deploy.md`, раздел 6).
- Обновление поверх v0.1.0: удалять приложение не нужно, данные сохраняются. Ключ подписи тот же, что у v0.1.0, поэтому APK
  ставится поверх.
- Подпись: SHA-256 сертификата должен быть
  `93:C1:E9:80:6A:48:D8:77:3B:C9:85:A2:5A:37:E6:28:C3:27:E3:F8:0E:86:A0:BD:AE:02:2D:E7:6D:64:4B:86`.
  Сверьте его с отпечатком, который вы сохранили при создании ключа (`apksigner verify --print-certs`). Если не совпадает,
  не ставьте APK и напишите.

## Installing

- Tablet: `overdrive-ride-0.2.0.apk`.
- Phone: `overdrive-companion-0.2.0.apk` (a placeholder for now).
- The server is not installed from an APK. On the host: `git pull --ff-only` and `docker compose up -d --build` (`docs/deploy.md`, section 6).
- Updating over v0.1.0: no uninstall is needed, data is kept. The signing key is the same as v0.1.0's, so the APK installs over it.
- Signature: the certificate SHA-256 should be
  `93:C1:E9:80:6A:48:D8:77:3B:C9:85:A2:5A:37:E6:28:C3:27:E3:F8:0E:86:A0:BD:AE:02:2D:E7:6D:64:4B:86`.
  Compare it with the fingerprint you saved when you made the key (`apksigner verify --print-certs`). If it differs, do not install
  the APK and tell us.
